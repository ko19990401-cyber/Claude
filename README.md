# 長時間音声 文字起こし・要約ツール

会議・研修・インタビューの録音を、**長さの制約を意識せず**テキスト化し、そのまま用途別の要約
（議事録・復命書・要点抽出など）へ切り替えられるローカルWebアプリです。

仕様書 v1.0 に基づく実装で、Phase 1〜4（MVP／話者と要約／長時間対応／体験の作り込み）まで
を含みます。手元のPCで動かしたまま Tailscale 経由でスマートフォンから使うこともできます（§2.5）。

```
ブラウザ（素のHTML/CSS/JS・ビルド不要）
   │ HTTP / SSE
ローカルAPIサーバ（Node.js + Hono, :8787）
   ├─ APIキーの秘匿（.env）           ├─ ffmpeg による音声前処理
   ├─ ASR APIへの投げ込みとポーリング  └─ LLMへの要約リクエスト（ストリーミング）
   ▼                    ▼
ASR API（話者分離対応）   Claude API（要約・整形）
```

---

## 1. セットアップ

### 必要なもの

| | 用途 | インストール |
|---|---|---|
| Node.js 20+ | サーバ実行 | https://nodejs.org |
| ffmpeg | 音声前処理（必須） | macOS `brew install ffmpeg` / Ubuntu `sudo apt install ffmpeg` / Windows `winget install Gyan.FFmpeg` |
| ASRのAPIキー | 文字起こし | ElevenLabs / AssemblyAI / Deepgram のいずれか |
| Anthropic APIキー | 要約 | https://console.anthropic.com |

### 手順

```bash
npm install
cp .env.example .env     # APIキーを記入する
npm run doctor           # ffmpeg とAPIキーの設定を確認する
npm run dev              # → http://localhost:8787
```

`npm run doctor` は起動前チェックです。ffmpeg の有無、各APIキーの設定状況、データ
ディレクトリの作成可否をまとめて表示します。

APIキーは `.env` にのみ置かれ、フロントエンドへは一切渡りません（`.gitignore` 済み）。

## 2. 使い方

1. **ホーム** — 音声・動画ファイルをドラッグ＆ドロップ。再生時間を読み取って
   **推定処理時間と推定コスト（円）**を表示し、実行前に確認できます。
2. **処理中** — 前処理 → 送信 → 文字起こし の各フェーズと経過・推定残り時間を表示。
   画面を閉じても処理は継続し、完了時にブラウザ通知が届きます。
3. **結果** — 上部タブで「文字起こし／要約」を切替。

### 文字起こしタブ

- セグメントをクリックすると**その時刻から音声再生**。再生位置は自動でハイライト・追従します。
- テキストは直接編集でき、編集したセグメントには印が付きます。
- 話者名はチップをクリックしてその場で変更。**全セグメントへ即時反映**されます。
- 全文検索（インクリメンタル・ヒット箇所へジャンプ）。
- 3時間の音声（数千セグメント）でも滑らかに動くよう**仮想スクロール**で描画します。

キーボード: `Space` 再生/停止、`Shift+←/→` 5秒送り戻し。

### 要約タブ

プリセットを選んで「要約を生成」。生成中の文章はストリーミングで流れます。

| ID | 名称 | 出力内容 |
|---|---|---|
| `minutes` | 議事録 | 日時・出席者・議題ごとの発言要旨・決定事項・保留事項 |
| `report` | 出張報告／復命書 | 用務・日時・場所・内容・所見・今後の対応（です・ます調の公用文体） |
| `brief` | 3行要約 | 結論・根拠・次の行動を各1文 |
| `outline` | 章立て要約 | 時系列の見出し＋各章3〜5行＋タイムスタンプ |
| `actions` | ToDo・決定事項抽出 | 「誰が・何を・いつまでに」の表形式 |
| `qa` | 質疑応答抽出 | 質問と回答のペアのみ |
| `custom` | 自由記述 | プロンプトを直接記述（過去の入力を再利用可） |

**文字起こしは保持されるので、プリセットを変えて何度でも作り直せます。**
生成した要約は並べて保存され、いつでも切り替えて閲覧できます。

要約内の `[00:12:34]` はクリックできます。押すとその時刻の音声が再生される
——**要約から元発言へ遡れる**のが本ツールの実用上の核心です。

### 用語辞書

固有名詞や専門用語の認識を、二段構えで補正します。

| 段 | 手段 | 内容 |
|---|---|---|
| 1段目 | ASRのカスタム語彙 | 文字起こし前にASRへ用語を渡し、認識そのものを補正（AssemblyAI / Deepgram が対応） |
| 2段目 | 置換辞書 | `誤り → 正` を完全一致・正規表現で置換。1段目で拾えない表記ゆれを吸収 |

置換履歴は保存され、**ワンクリックで取り消せます**。辞書はプロジェクト単位で保存され、
次回以降のジョブに引き継がれます。

### エクスポート

`.md` / `.txt` / `.srt` / `.vtt` のダウンロードと、クリップボードへのコピー。
「文字起こしのみ／要約のみ／両方」とタイムスタンプの有無を選べます。

## 2.5 スマートフォンから使う

フロントとAPIを1プロセスで配信する構成なので、スマホからも同じ画面がそのまま使えます。
やり方は2つあります。

| | 費用 | PCの電源 | 向いている場合 |
|---|---|---|---|
| **A. 手元のPC + Tailscale** | 無料 | 必要 | 個人利用。**音声がクラウドのディスクに残らない** |
| **B. コンテナをクラウドへ** | 月1,000円程度〜 | 不要 | いつでも使いたい、PCを起動しておけない |

---

### A. 手元のPC + Tailscale（推奨）

PCとスマホを同じ仮想LAN（tailnet）に入れて直接つなぎます。公開URLを持たないので、
録音データが第三者のサーバーに置かれることがありません。
Tailscale の Personal プランは無料です。

**1. Tailscale をPCとスマホの両方に入れて、同じアカウントでログインする**

```bash
# macOS
brew install --cask tailscale
# Linux
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

スマホは App Store / Google Play から Tailscale アプリを入れてログインします。

**2. 管理画面で HTTPS 証明書を有効にする**

[Tailscale 管理コンソール](https://login.tailscale.com/admin/dns) の DNS ページで
**MagicDNS** と **HTTPS Certificates** を有効にします。これは見た目の問題ではなく、
**完了通知（Notification API）とクリップボードコピーがHTTPSでしか動かない**ためです。

**3. サーバを起動して tailnet へ公開する**

```bash
npm run dev                    # 別のターミナルで起動したままにする
tailscale serve --bg 8787      # tailnet 内にHTTPSで公開する
```

`tailscale serve` は tailnet からの通信を `127.0.0.1:8787` へ中継します。
**`HOST` は既定の `127.0.0.1` のままにしてください。** `0.0.0.0` にすると
同じWi-Fiにいる他の端末からも直接届いてしまい、わざわざ Tailscale を使う意味が薄れます。

起動時に、スマホで開くURLがログに出ます。

```
✔ http://localhost:8787 を開いてください
✔ スマホからは https://macbook.tail1234.ts.net （Tailscale・HTTPS）
```

**4. スマホでそのURLを開く**

以上です。tailnet の外からは一切見えません。

**公開をやめるとき**

```bash
tailscale serve --bg=false 8787   # 公開を解除
tailscale serve status            # 現在の設定を確認
```

> ⚠️ `tailscale funnel` は**インターネット全体**へ公開するコマンドです。
> 本ツールでは使わないでください。使う場合は必ず `AUTH_USER` / `AUTH_PASSWORD` を設定してください。

**Basic認証について**

tailnet 内に閉じているので必須ではありませんが、設定しておけば端末を紛失したときの
保険になります。`.env` に `AUTH_USER` と `AUTH_PASSWORD` を書けば有効になります。

**PCがスリープすると使えません。** 常時使いたい場合は B を検討してください。

---

### B. コンテナをクラウドへ置く

ffmpeg 同梱の `Dockerfile` を用意しています。**公開する前に必ず認証を設定してください。**

- `AUTH_USER` と `AUTH_PASSWORD` の両方を設定すると、画面・API・SSE・音声配信の
  すべてに Basic 認証がかかります。
- `REQUIRE_AUTH=true` にしておくと、認証が未設定のままではサーバが起動しません
  （同梱のデプロイ設定では既定で有効です）。
- Basic認証は資格情報を平文で送るため **HTTPSが前提**です。Fly.io / Render は自動で付きます。

**Fly.io**（東京リージョン・永続ボリュームあり。Launch $5/月＋ボリューム約$1.5/月）

```bash
fly launch --no-deploy --copy-config      # fly.toml の app 名を自分のものへ書き換える
fly volumes create data --size 10 --region nrt
fly secrets set \
  ELEVENLABS_API_KEY=... \
  ANTHROPIC_API_KEY=... \
  AUTH_USER=yourname \
  AUTH_PASSWORD='長めのパスフレーズ'
fly deploy
```

ボリューム10GBは、前処理後の音声（1時間あたり約10MB）で約1,000時間分に相当します。

**Render** — `render.yaml` を Blueprint として読み込み、ダッシュボードで各キーを入力します。
永続ディスクは有料プランが必要です（**無料プランはディスクを付けられず、再起動で
データが消える**ため使えません）。

**VPS・自宅サーバ** — `docker compose up -d --build`。前段に HTTPS を終端する
リバースプロキシ（Caddy / Nginx + Let's Encrypt など）を置いてください。

---

### ホーム画面に追加する

PWAマニフェストとアイコンを同梱しています。iOS Safari は「共有 → ホーム画面に追加」、
Android Chrome は「アプリをインストール」で、単独アプリのように起動できます。
アイコンを変えたい場合は `tools/make-icons.mjs` を編集して `node tools/make-icons.mjs`
を実行してください。

**iOS では、ホーム画面に追加したときだけ完了通知が届きます。** ブラウザのタブから
開いている間は通知が出ません。

### スマホで使う際の注意

- **アップロードは回線速度に依存します。** 1時間の録音は元ファイルで数十〜数百MBに
  なるため、モバイル回線ではWi-Fiより時間がかかります（圧縮はサーバ側で行うので、
  送信するのは元ファイルです）。
- アップロード中は画面を閉じないでください。送信後の前処理・文字起こしはサーバ側で
  継続するので、画面を閉じても問題ありません。
- 画面をロックするとSSEの接続は切れますが、再度開くと進捗の履歴から復元します。

## 3. 設定（.env）

| 変数 | 既定値 | 内容 |
|---|---|---|
| `ASR_PROVIDER` | `elevenlabs` | `elevenlabs` / `assemblyai` / `deepgram` |
| `ELEVENLABS_API_KEY` 他 | — | 選んだエンジンのAPIキー |
| `ASR_LANGUAGE` | `ja` | 認識言語（`auto` で自動判定） |
| `ANTHROPIC_API_KEY` | — | 要約に使用 |
| `SUMMARY_MODEL` | `claude-opus-5` | 既定の要約モデル。画面から切替可 |
| `SUMMARY_EFFORT` | `medium` | 思考の深さ。`low` ほど安価・高速 |
| `AUTH_USER` / `AUTH_PASSWORD` | — | 両方設定すると全体にBasic認証がかかる |
| `REQUIRE_AUTH` | — | `true` で、認証未設定なら起動を拒否する |
| `PORT` | `8787` | サーバのポート |
| `HOST` | `127.0.0.1` | コンテナ等で外部から接続するなら `0.0.0.0` |
| `DATA_DIR` | `./data` | 音声・結果の保存先 |
| `USD_JPY` | `150` | コスト表示の換算レート |
| `HIERARCHICAL_THRESHOLD` | `120000` | この文字数を超えたら階層要約に切り替える |
| `CHUNK_CHARS` / `CHUNK_OVERLAP_CHARS` | `20000` / `400` | 階層要約の分割サイズ |
| `MAP_CONCURRENCY` | `4` | 階層要約 Map 段の同時実行数 |

### ASRエンジンの選定について

仕様書 §7.2 のとおり、**実データで比較してから決めてください**。公開されている
精度ベンチマークの多くは英語音声で測定されたもので、日本語の実力を直接は反映しません。

5〜10分の代表音声（複数話者・専門用語を含むもの）を用意し、`.env` の `ASR_PROVIDER` を
切り替えて同じ音声を処理し、以下を採点するのが確実です。

- 固有名詞・専門用語の正答率
- 話者交代点のずれ（特に相槌・かぶり発言）
- 句読点と改行の自然さ

エンジン層は差し替え可能な抽象化にしてあります（`server/asr/`）。新しいベンダーを
足すときは `submit` / `poll` を実装して `server/asr/index.js` に登録するだけです。

| エンジン | 話者分離 | 概算単価 | 特徴 |
|---|---|---|---|
| ElevenLabs Scribe（既定） | 基本料金込み | 約 $0.004/分 | 非英語の評判が良い。同期API |
| AssemblyAI Universal | 込み | 約 $0.0037/分 | 非同期バッチAPI。中断・再開に最も強い。カスタム語彙対応 |
| Deepgram Nova-3 | 追加課金 | 約 $0.0068/分 | 処理が速い。カスタム語彙対応 |

> 価格は各社公開情報に基づく概算です。実装前に必ず公式ページで確認してください。

## 4. 長時間音声の扱い

### 音声は自前で分割しない（原則）

主要な話者分離対応ASRは数時間の音声をそのまま受け付けます。自前でチャンク分割すると
「チャンク1の話者A」と「チャンク2の話者A」が別人になり、分割点で単語も切れます。
そのため前処理後のファイルがAPI上限に収まる限り、**1本のまま送信します**。

前処理（モノラル / 16kHz / Opus 24kbps）で 1時間のWAVは約600MB → 約10MB になるため、
10時間の音声でも約110MBで、実質どのベンダーの上限にも収まります。

### 上限を超えた場合のみ分割

1. `silencedetect`（-35dB / 0.7秒以上）で**無音区間を検出**し、その中央を境界にする
2. 前後に**のりしろ**を持たせて切り出す（のりしろ込みでAPI上限に収まるよう長さを決定）
3. のりしろ区間のテキスト一致で**重複を除去**
4. のりしろ区間の発言を突き合わせて**話者ラベルを対応付け**（対応が取れない話者は
   未使用のラベルへ順に割り当て、足りなければ新規採番）
5. UIとエクスポートに**警告バッジ**を表示（精度低下の可能性を明示）

### 階層要約

全文が閾値（既定12万字 ≒ 4〜5時間の会議）を超えると、自動的に階層要約へ切り替わります。

```
① 分割   話者ターン境界を尊重しつつ約20,000字ごと。前チャンク末尾400字をオーバーラップ
② Map    各チャンクを「事実の抽出」として中間要約（並列・effort=low でコストを抑制）
③ Reduce 中間要約群を結合し、選択されたプリセットの形式へ整形（ストリーミング）
```

**中間要約は保存され、プリセットを変えた再生成では ② を再実行しません**（③ のみやり直す）。
文字起こしを編集した場合は内容ハッシュが変わるため、② から作り直します。

一括要約でも、文字起こし全文にプロンプトキャッシュを効かせているため、
プリセット違いの再生成は入力側の費用がほぼかかりません。

## 5. コストの目安

1時間の音声、文字起こし＋要約1回（150円/USD換算）：

| 項目 | 概算 |
|---|---|
| 文字起こし（話者分離込み） | 約 36〜60円 |
| 要約（入力 約4万字／出力 約3千字） | 約 20〜40円 |
| **合計** | **約 60〜100円／時間** |

実際の使用量は要約生成後に画面へ表示されます（`約38.2円 / 出力2,400トークン` のように）。
コストを抑えたい場合は、要約モデルを Sonnet 5 や Haiku 4.5 に切り替えるか、
`effort` を `low` に下げてください。

## 6. 中断・再開・失敗時の挙動

- ブラウザを閉じても処理は継続します。再度開くとSSEの履歴から経過を復元します。
- 通信失敗は指数バックオフで3回まで自動リトライします。
- **非同期API（AssemblyAI）**を使っている場合、サーバを再起動しても保存済みの
  ジョブIDからポーリングを再開します。
- 同期API（ElevenLabs / Deepgram）でサーバが落ちた場合は、アップロード済みの音声を
  保持したまま「再試行」ボタンを表示します。
- 要約が失敗しても、文字起こしは別レコードとして保存されているため失われません。

## 7. データの置き場所

```
data/
  jobs/<jobId>/job.json          … メタ情報・話者・エンジン・状態
  jobs/<jobId>/segments.json     … 文字起こし本体
  jobs/<jobId>/intermediate.json … 階層要約の中間要約
  jobs/<jobId>/summaries/*.json  … 要約（1件1ファイル）
  audio/<jobId>.ogg              … 前処理済み音声
  glossaries/*.json              … 用語辞書
```

`segments` と `summaries` を完全に分離しているため、要約の作り直しが文字起こしに
影響しません。`speakers[].label` は参照テーブルとして持ち、セグメント側は `speakerId`
だけを持つので、話者のリネームは1箇所で済みます。

ブラウザ側にも IndexedDB に結果を保存しているため、サーバが落ちていても
一度開いたジョブは閲覧できます（編集・生成はできません）。

削除は**物理削除**です。ジョブディレクトリと音声ファイルの両方を消します。

## 9. テスト

```bash
npm test              # 全スイート
npm test pipeline     # 個別スイート（pipeline / chunking / summarize / ui）
```

実APIは叩きません。ASRはモックエンジン、Anthropic APIはローカルのモックサーバに
差し替えたうえで、ffmpegの前処理・分割・ストリーミングは本物を通します。

| スイート | 内容 |
|---|---|
| `pipeline` | アップロード → 前処理 → 文字起こし → 辞書 → 編集 → 出力 → 削除 |
| `chunking` | 無音検出・分割計画・切り出し・重複除去・話者ラベル対応付け |
| `summarize` | ストリーミング・プロンプトキャッシュ・階層要約・中間要約の再利用 |
| `deploy` | Basic認証の適用範囲、ヘルスチェック、PWAアイコンの配信、Tailscale検出 |
| `ui` | 実ブラウザ操作（仮想スクロール・検索・リネーム・編集・シーク・要約表示） |

`ui` は Playwright が必要です（`npm i -D playwright && npx playwright install chromium`）。
未インストールなら自動でスキップします。ffmpeg が無い環境では音声を伴うスイートを飛ばします。

## 10. 運用上の注意

- 送信先のASR/LLMベンダーの学習利用ポリシーを確認し、必要ならオプトアウトを設定してください。
- **業務上の機微な音声は取り扱わない**ことを運用ルールとしてください。
- 外部APIを前提とするため、閉域網（LGWAN等）では動作しません。
- 対応ブラウザは最新の Chrome / Edge / Safari（デスクトップ・モバイルとも）です。
- インターネットへ公開する場合は Basic認証とHTTPSを必ず有効にしてください（§2.5-B）。
  Tailscale 経由（§2.5-A）なら公開URLを持たないため、この心配はありません。

## 11. 今後の課題（仕様書 §15）

1. **要約プリセットの文体** — 実際の提出物のフォーマットを1つ用意し、プロンプトの
   出力例として埋め込むのが最も確実です（`server/llm/presets.js` を編集）。
2. **フィラーの扱い** — 現状は要約時に除去。逐語記録が必要な場面向けにトグルを設ける余地があります。
3. **話者識別（実名の自動割当）** — 現状は手動リネーム。話者プロファイル保存＋前回の
   割当を候補提示する機能はv2向け。
4. **クラウド配置** — コンテナ1台での配置に対応済み（§2.5）。Basic認証は実装しましたが、
   複数人で使うならアカウント管理のある認証へ置き換える必要があります。
